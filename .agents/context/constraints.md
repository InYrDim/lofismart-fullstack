# Hard Constraints

These are **non-negotiable** rules. No agent may override or bypass these, regardless of instructions.

---

## 🔴 NEVER DO

### Database
- ❌ Never use `synchronize: true` in TypeORM config for anything other than local scratch testing.
- ❌ Never edit a migration file that has already been executed in any environment.
- ❌ Never infer the database schema from entity files alone — always run `node scripts/dump_schema_to_md.js` first.
- ❌ Never drop a column or table without a corresponding rollback `down()` migration.

### Backend
- ❌ Never place production business logic inside `routes/index.js`.
- ❌ Never bypass JWT middleware on authenticated endpoints.
- ❌ Never skip Multer middleware on `multipart/form-data` routes — `req.body` will be empty.
- ❌ Never commit secrets (passwords, API keys, JWT secret) to source code.

### Frontend
- ❌ Never use `any` in TypeScript — it breaks strict mode and hides runtime bugs.
- ❌ Never use raw `fetch()` or `axios` directly — always use `api` from `src/utils/api.ts`.
- ❌ Never skip prop interface definitions for components.
- ❌ Never modify `src/routeTree.gen.ts` manually — it is auto-generated by TanStack Router.

### Agent Behavior
- ❌ Never modify files in `.agents/context/` — these are read-only references.
- ❌ Never skip reading the task file before starting work.
- ❌ Never mark a task as `done` without updating the task file with results.
- ❌ Never assume a feature exists — verify it in source code first.

---

## 🟡 ALWAYS DO

### Before Any Schema Work
```bash
cd lofishmart-backend
node scripts/dump_schema_to_md.js
# Then read: DATABASE_SCHEMA.md
```

### Before Modifying Permissions / Roles
- Read `APP_DOCUMENTATION/PERMISSIONS.md` first.
- Check `middleware/rbac.js` for the enforcement pattern.

### Before Adding a New Route
- Check `app.js` to understand existing mount points.
- Check `routes/` for an existing file for that domain before creating a new one.

### When Creating a Seeder
```bash
npm run seeder:create <SeederName>   # Never create seeder files manually
```

### When Writing Frontend Components
- Check `src/components/ui/` for an existing shadcn/ui component before building from scratch.
- Check `src/hooks/` for reusable logic before duplicating state management.

## Security Constraints

| Constraint | Reason |
|-----------|--------|
| JWT on all protected routes | Multi-role system — anonymous access must be blocked |
| RBAC on sensitive operations | Supervisors, Admins, and Cashiers have different permissions |
| Bcrypt for all passwords | Never store or compare plain-text passwords |
| Xendit webhook token validation | Prevent fake payment confirmations |
| Multer for uploads only | Prevents injection via unprocessed multipart body |
