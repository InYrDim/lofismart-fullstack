# Plan: Modernize ItemModal Layout in kelolagudang/receive

## Current State Analysis
The `ItemModal` component in `_protected.kelolagudang.receive.lazy.tsx` has a functional but dated layout:
- Quantity fields are split into two separate grid sections
- Quick-add buttons are scattered below each input
- Unit badge appears conditionally with abrupt show/hide
- No clear visual hierarchy or section grouping
- Price and batch fields are in a basic grid
- Overall spacing feels cramped

## Design System Context
The codebase uses shadcn/ui components with:
- Color scheme: Emerald primary (`emerald-600`, `emerald-50`, etc.)
- Card components available: `Card`, `CardHeader`, `CardContent`, `CardFooter`
- Badge component with variants (success, default, etc.)
- Label component for form accessibility
- Rounded corners: `rounded-lg`, `rounded-xl`
- Shadows: `shadow-sm`, shadows with opacity
- Design tokens via CSS variables (bg-card, text-card-foreground, etc.)

## Modernization Goals
1. **Clear visual hierarchy** - Group related fields with cards and section headers
2. **Better spacing** - Use generous padding and gaps
3. **Improved quantity section** - All three quantities (purchased, accepted, rejected) in one cohesive layout
4. **Integrated unit indicator** - Show unit badge prominently, possibly within the product selector area
5. **Consistent form structure** - Use Label components, proper input grouping
6. **Smooth interactions** - Maintain existing functionality while improving UX
7. **Responsive design** - Ensure it works well on mobile and desktop

## Proposed Layout Structure

### Section 1: Product Selection (Card)
- Card with subtle border and light background
- Product Combobox with clear label
- Unit badge displayed inline next to product name or below selector
- Optional: Show product category or additional info when selected

### Section 2: Quantity Input (Card)
- Card with header "Quantity Details"
- Three-column layout on desktop, stacked on mobile:
  - **Purchased Qty**: Input with +/- buttons, quick-add chips below
  - **Accepted Qty**: Input with +/- buttons, quick-add chips below
  - **Rejected Qty**: Input with +/- buttons, quick-add chips below
- Each column has:
  - Clear label with unit (kg/ekor)
  - Integrated number spinner styling
  - Quick-add value buttons in a compact row
- When rejected_qty > 0, show reject reason field below the three columns (full width)

### Section 3: Pricing & Batch (Card)
- Two-column grid:
  - Harga / Unit (with currency prefix or label)
  - Batch (optional)
- Clean, minimal inputs

### Footer
- Existing ModalFooter with Cancel and Submit buttons
- Submit button disabled until product is selected (already implemented)

## Visual Enhancements
- Use `Card` with `border-gray-200`, `shadow-sm`, `rounded-xl`
- Card headers with subtle text and optional icon
- Consistent `gap-4` or `gap-6` between sections
- Use `Label` component for all form fields
- Badge for unit display: `Badge variant="success"` or custom styling
- Input fields: maintain existing Input component but with better grouping
- Buttons: use existing Button with `variant="outline"` for controls
- Smooth transitions when reject reason appears (optional: add simple fade animation)

## Responsive Behavior
- Mobile: Single column stack for all sections
- Tablet (md): 
  - Quantity section: 3 columns
  - Pricing section: 2 columns
- Desktop: Same as tablet with adequate max-width

## Implementation Approach
1. Replace outer `div` containers with `Card` and `CardContent` components
2. Add section headers using `div` with heading styles (or CardHeader if appropriate)
3. Restructure quantity section into a responsive grid (grid-cols-1 md:grid-cols-3)
4. Move quick-add buttons inside each quantity column for better association
5. Place reject reason field below quantity grid when needed (conditional full-width row)
6. Use Label component for all input labels
7. Keep unit badge visible in product section, possibly with better styling
8. Maintain all existing state logic and handlers
9. Add `disabled` prop to all interactive elements when no product selected (already done)
