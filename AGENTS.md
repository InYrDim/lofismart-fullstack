## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

When the user types `/graphify`, invoke the `skill` tool with `skill: "graphify"` before doing anything else.

Rules:
- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- Dirty graphify-out/ files are expected after hooks or incremental updates; dirty graph files are not a reason to skip graphify. Only skip graphify if the task is about stale or incorrect graph output, or the user explicitly says not to use it.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).

## Architecture

LofiSmart is a fullstack POS/inventory system for multi-branch fish/seafood retail. Three packages, not a monorepo workspace — each has its own `node_modules` and lockfile.

- `lofishmart-backend/` — Express 4 + TypeORM + MySQL 8, CommonJS (no ESM)
- `lofishmart-frontend/` — React 19 + Vite (Rolldown) + Tailwind 4 + TanStack Router, ESM
- `e2e/` — Playwright tests, CommonJS

## Setup

```bash
bash start-dev.sh   # Copies .env.dev → .env, starts Docker (MySQL), backend, frontend
```

Or manually:
```bash
cp .env.dev .env && cp lofishmart-backend/.env.dev lofishmart-backend/.env
cp docker-compose.dev.yml docker-compose.yml
docker compose up -d
cd lofishmart-backend && npm start        # :3000
cd lofishmart-frontend && npm run dev     # :5173
```

## Key Commands

```bash
# Lint → Typecheck → Test (frontend only has this pipeline)
cd lofishmart-frontend && npm run lint && npm run build && npm run test:run

# Backend tests (requires running MySQL)
cd lofishmart-backend && npx jest
cd lofishmart-backend && npx jest tests/inventoryController.test.js  # single file

# Frontend tests (no DB needed, API mocked)
cd lofishmart-frontend && npx vitest run
cd lofishmart-frontend && npx vitest run src/test/services/auth.service.test.ts  # single file

# E2E (requires all services running)
cd e2e && npx playwright test
cd e2e && npx playwright test --project=admin   # single role

# Full test suite
bash run-tests.sh
```

## Things That Will Trip You Up

- **Backend is CommonJS** — use `require`/`module.exports`, never `import`/`export`. Frontend is ESM.
- **`routes/index.js` is legacy/test only** — production routes go in separate files (`routes/product.js`, `routes/transaction.js`, etc.). Never put new business logic in `routes/index.js`.
- **`multipart/form-data` routes need Multer** — without it, `req.body` is empty. See `middleware/uploadFile.js`.
- **Known DB typos are intentional** — `werehouse` (not warehouse), `PeymentMethod` (not PaymentMethod), `totol_pcs_qty` (not total). Do not "fix" these.
- **Never run `synchronize: true`** in TypeORM for anything beyond scratch testing.
- **Never edit a migration that has already run** in any environment.
- **Before any schema work**: run `node scripts/dump_schema_to_md.js` in `lofishmart-backend/`, then read `DATABASE_SCHEMA.md`.
- **Always create migrations via CLI**: `npm run migration:create -- ./db/migrations/DescriptiveName` — never create migration files manually.
- **Frontend: never use `any`** — strict TypeScript mode is enforced.
- **Frontend: never use raw `fetch()` or `axios`** — use `api` from `src/utils/api.ts`.
- **Frontend: never edit `src/routeTree.gen.ts`** — it's auto-generated by TanStack Router.
- **E2E tests use role-based projects** — `setup` project runs first (auth), then `admin`/`kasir`/`gudang` run in parallel. Auth states saved to `playwright/.auth/`.

## Testing

| Layer | Tool | Requires DB |
|-------|------|-------------|
| Backend integration | Jest + supertest | Yes (MySQL) |
| Frontend unit | Vitest + jsdom + RTL | No (mocked) |
| E2E | Playwright | Yes (full stack) |

Backend test data uses `TEST*` ID prefix — auto-cleaned in `beforeEach`/`afterAll`.
